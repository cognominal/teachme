Scaled dot-product attention

One page: the four steps, the shapes, the two languages, the four ways it goes wrong.

The four steps

scores  = Q · KT
weights = softmaxrows( scores / √dk )
output  = weights · V
#StepShapeWhy it is there
1Q · KT(T×dk)·(dk×T) → T×Tdot product = similarity between one query and one key
2/ √dkT×Traw score spread grows as √dk; without it softmax saturates and gradients die
3softmaxrowsT×Teach row becomes a distribution: non-negative, sums to 1
4· V(T×T)·(T×dv) → T×dvoutput row i = weighted average of all rows of V

# PyTorch, written out, batched over leading dims (batch, heads)
def attention(Q, K, V):                       # (..., T, dk), (..., T, dk), (..., T, dv)
    dk = Q.shape[-1]
    scores = Q @ K.transpose(-2, -1) / dk ** 0.5
    return torch.softmax(scores, dim=-1) @ V  # (..., T, dv)

Sanity checks you can do by hand

  • One token: with T = 1 the only weight is 1, so the output equals the single value row. Any correct implementation reproduces this.
  • Identical rows: if every key row is the same, every weight in a row is 1/T — a plain average.
  • Sharpness: multiply the scaled scores by a constant c and the distribution sharpens as c grows; the scale 1/√dk exists to keep c ≈ 1.
  • Convexity: every output cell must lie between the smallest and largest value in that column of V. A weighted average can never leave the range of what it averages.
