The tensor idioms, in the order they appear

import math
import torch

torch.set_printoptions(precision=3, sci_mode=False)   # readable printing: no 1.2345e+00

T, dk = Q.shape          # tuple unpacking; Q.shape is torch.Size([T, dk])
dk = Q.shape[-1]         # same thing, last axis; -2 is the one before it

scores = Q @ K.transpose(-2, -1)   # @ is matmul. A * B would be element-wise — a different operation
scores = scores / dk ** 0.5        # ** is power; division is element-wise; dtype is preserved
weights = torch.softmax(scores, dim=-1)   # dim=-1: along the last axis, so each ROW sums to 1

weights.tolist()         # nested Python lists, for printing or handing to a browser page
float(weights[0, 0])     # a 0-dim tensor -> a number; .item() is the same thing

g = torch.Generator().manual_seed(7)      # reproducible randomness: same numbers on every run
torch.randn(4, 8, generator=g)

Q64 = Q.double()         # float32 (default) -> float64, when you want exact comparisons

Two habits that save the most time

Print the shape, not the tensor. print(x.shape) answers "why is this the wrong shape" in one line; printing a (64 × 64) tensor into a terminal answers nothing.

Prefer transpose(-2, -1) to .T. They agree for 2-D tensors; on anything with a batch or head axis .T reverses all the axes (and current PyTorch warns you).

Reshaping: view, reshape, transpose

x.shape                       # torch.Size — a tuple of axis lengths; negative indices count from the end
x.view(T, H, dh)              # reinterpret the same memory; raises if the layout does not match
x.transpose(0, 1)             # swap two axes — moves NO data, so the result is usually not contiguous
x.reshape(T, H * dh)          # transpose then flatten; copies only if it has to
x.contiguous().view(T, H*dh)  # the same, spelled out: make it contiguous, then view
x.permute(1, 0, 2)            # more than two axes at once
TrapWhat happens
.view() on a transposed tensorRuntimeError: view size is not compatible with input tensor's size and stride (at least one dimension spans across two contiguous subspaces). Use .reshape(...) instead. — the message names the fix.
The same .view sometimes worksWhen the strides happen to line up it succeeds, so a working .view proves nothing about your next reshape. Prefer .reshape after any transpose.
view(H, T, dh) where you meant view(T, H, dh)No error at all: both have the same element count, so the arrangement is simply wrong. Only the values reveal it.
A slice is not contiguousx[:, :4].view(...) fails the same way even though the slice "looks" dense — slicing is a view with a stride.
.T on anything above 2-DIt reverses all axes, not the last two. Use transpose(-2, -1) in attention code.

Masking: the idioms and the traps

mask   = torch.tril(torch.ones(T, T))        # 1 = may look, 0 = blocked; diagonal included
scores = scores.masked_fill(mask == 0, float("-inf"))   # fill where the condition is True
scores = torch.where(mask == 0, float("-inf"), scores)  # same edit, not in place

blocked = (mask == 0)                        # a bool tensor
scores.masked_fill(blocked, float("-inf"))   # a bool mask works directly
inverted = ~mask.bool()                      # ~ flips a bool tensor; mask.bool() converts 0/1
TrapWhat happens
float("-inf") is a Python float, not math.infBoth spellings are fine (-math.inf too). What matters is that it is large enough that exp underflows: any value below about −100 gives exactly 0 in float32.
0.0 * float("-inf")nan — IEEE arithmetic, not a Python quirk. Dividing or multiplying by a positive constant keeps −∞; multiplying by 0 destroys it.
a whole row at −∞torch.softmax gives nan (0/0), and the nan spreads through the next matmul into the whole batch.
mask of the wrong shapeRuntimeError: The size of tensor a (3) must match the size of tensor b (4) at non-singleton dimension 1 — the mask has to be (T, T) for a (T, T) score matrix.
masking after the softmaxNo error, no nan — the rows just quietly stop summing to 1. This one has to be caught by a test, not by reading the output.
