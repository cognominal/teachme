Shape and storage

TermMeans
scalarone number.
vectora fixed-length list of numbers. In this course, one token's features.
matrixa list of vectors — a sequence of tokens. Written in code as an array of arrays.
shaperows × columns, written (T × d). For a batch, the leading axes count the batch: (B × T × d).
row / columnA row of a token matrix is one token; a column is one feature across all tokens.
element (entry)one cell: A[i][j].
dimensionThe length of one axis. Because almost every error is an axis mix-up, PyTorch names axes in code (dim=-1) rather than describing them.
axis / dimOne direction of a tensor. -1 is the last axis, -2 the one before it. Ran into in lesson 00.
tensorAn n-dimensional array of numbers — torch.Tensor from lesson 01 on. A matrix is a 2-D tensor; a batch of sequences is a 3-D one. Same numbers as the nested lists in lesson 00, with the maths built in.
dtypeThe number type inside a tensor. float32 is what torch gives you by default and what a real model trains in; comparisons in this workspace's checks use a 1e-5 tolerance because float32 arithmetic lands within ~4e-8 of the same maths in float64.
dim / axis argumentWhich axis an operation runs along. In attention, dim=-1 on softmax means "along each row". Ran into in lesson 00, load-bearing in lesson 01.
batchSeveral sequences processed at once, as an extra leading axis — the leading axes pass through matmul untouched. Ran into in lesson 00; proper treatment with heads later.

Operations

TermMeans
dot productTwo equal-length vectors → one number: multiply pairwise, add. Measures similarity.
matmul (matrix product)(m × n) · (n × p) → (m × p); cell (i, j) is row i of the left operand dotted with column j of the right. Inner numbers must match; outer ones survive.
transposeSwap rows and columns: (m × n) → (n × m). In PyTorch transpose(-2, -1); .T is only safe on 2-D tensors.
element-wise productA * B in PyTorch: matching cells multiply, nothing mixes. Never what attention wants.
softmaxTurns a list of numbers into a distribution: non-negative, summing to 1. Applied per row in attention.
saturateWhat a softmax does when its inputs are large: nearly all the mass lands on one entry, so the result is almost one-hot and gradients vanish. The 1/√dk scale exists to prevent it.

The attention core

TermMeans
tokenOne element of the sequence — roughly a word-piece. Rows of every token matrix.
embedding / featuresThe d numbers that represent a token. Everything attention computes is a new set of these.
query (q)What a token is looking for. A row of Q.
key (k)What a token offers for matching. A row of K.
value (v)What a token hands over once matched. A row of V.
self-attentionQ, K and V all projected from the same input rows, by three learned matrices WQ, WK, WV.
score (logit)One cell of Q · KT: an unnormalised similarity. Not a weight until softmax has run.
attention weightOne cell of the softmaxed score matrix: how much of that key's value the query takes. Each row sums to 1.
weighted averageSum of values scaled by weights. Row i of attention's output is a weighted average of all of V's rows.
scaleDividing scores by √dk before softmax, to hold the spread near 1.
dk / dvWidth of a query/key vector; width of a value vector. They can differ; the output is (T × dv).
T (context length)Number of tokens. Q.length, scores.shape[-1].
causal maskMaking token i unable to see tokens after it: disallowed score cells are set to −∞ before softmax, which gives them weight exactly 0. Taught in lesson 02; built in code as torch.tril(torch.ones(T, T)).
maskA (T × T) tensor of 0s and 1s given to attention: 1 = this query may look at that key, 0 = it may not. Edited into the scores; it is not a weight the model learns.
masked_fillscores.masked_fill(mask == 0, float("-inf")) — the line that applies a mask. The filler must be negative enough that exp underflows to exactly 0; 0 itself would invite the blocked keys in.
autoregressivePredicting each token from the ones before it. The causal mask is what makes one forward pass over a whole sequence give T such predictions at once, and what makes the KV cache valid later.
is_causalThe flag that asks a fused kernel (F.scaled_dot_product_attention) to apply the causal triangle itself, so the (T × T) mask is never built. is_causal=True is the causal mask expressed as intent.
headOne independent attention computed over a slice of the width; H of them run in parallel and their outputs are concatenated. Taught in lesson 03: x.view(T, H, dh).transpose(0, 1).
d_head (dh)The width of one head, C / n_head. It is the divisor in that head's 1/√d_head scale — not the full width C, which would over-flatten every head.
WO (output projection)The learned (C × C) matrix applied to the concatenated heads (Concat(head₁…head_h)WO). Without it a head can only ever write into its own columns; with it, heads influence each other's downstream contribution.
MQA / GQAMulti-query and grouped-query attention: fewer key/value heads than query heads, so the cache that generation reloads every step is smaller. MQA shares one K/V head; GQA shares one per group. Ran into in lesson 03.
KV cacheKeys and values remembered from earlier steps so generation does not recompute them. Later.
