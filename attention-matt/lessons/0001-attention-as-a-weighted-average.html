Attention is a weighted average

Four steps, five lines of PyTorch, one heatmap your own torch code produces.

From here on, the code is real PyTorch. You write two functions in exercises/0001_attention.py, run ./bin/grade 0001, and the checks compare your numbers against an independent implementation on random tensors. This page explains the four steps, gives you the Python you need, and then draws your output.

Prerequisites: Lesson 00 — one row per token, and inner numbers must match for a product to exist. Every shape below comes from there. New to Python? §2 is the whole syntax this lesson uses.

The one idea

A Python dict returns one value for a key. Attention is a lookup that returns a blend of every value in the table, weighted by how well the query matches each key. That's it. Everything else is bookkeeping about those weights.

1 · Three roles, one input

Every token in the sequence plays three parts, via three separate vectors:

VectorRolePlain-English test
query (q)what this token is looking for"I am the word it — I need a noun."
key (k)what this token offers for matching"I am the word trophy — I am a noun."
value (v)what this token hands over once matched"Here is what I contribute to the mix."

In self-attention all three come from the same input rows, multiplied by three learned matrices WQ, WK, WV. This lesson takes Q, K and V as given, so the mechanism is all that is left to see.Roy, Vosoughi & Shazeer call this a "fuzzy" lookup; the softness is the point — nothing is ever exactly matched or exactly ignored.

2 · The Python you need (all of it)

Six constructs, and the transposition of the habits you already have. Nothing here is subtle — but tensor code is where a JS/Perl/C developer's reflexes go wrong, so read this once with attention.

import math
import torch

def attention_weights(Q, K):                # def name(args): — the colon opens a block
    dk = Q.shape[-1]                         # .shape is a tuple; [-1] is the last axis — so dk here
    scores = Q @ K.transpose(-2, -1)          # @ is matmul (not element-wise); transpose(-2,-1) swaps the last two axes
    scores = scores / dk ** 0.5               # ** is power, as in JS; no Math. prefix
    return torch.softmax(scores, dim=-1)      # dim=-1 = along the last axis = each row

3 · The four steps

weights = softmaxrows( Q · KT / √dk )
output = weights · V
  1. Score. Q @ K.transpose(-2, -1) dots every query with every key. Entry (i, j) is "how much does token i's query like token j's key". The result is T × T: one row per token asking, one column per token answering.
  2. Scale. Divide by √dk — the square root of a query's width, Q.shape[-1].
  3. Normalise. torch.softmax(scores, dim=-1) — along each row, so each row becomes a probability distribution: non-negative, sums to 1.
  4. Mix. weights @ V. Row i of the output is the weighted average of all value rows, as chosen by query i.
StepPyTorchShape (T tokens, dk key width, dv value width)
inputsQ, K, V(T, dk), (T, dk), (T, dv)
transposeK.transpose(-2, -1)(dk, T)
scoresQ @ K.transpose(-2, -1)(T, T)
weightstorch.softmax(scores / dk ** 0.5, dim=-1)(T, T)
outputweights @ V(T, dv)
Why the √dk exists

Dot products of d independent terms grow with d: the spread of a raw score is about √dk. With dk = 64 typical scores land near ±8 either side of zero, and softmax([8, 0, −8]) is [0.9997, 0.0003, 0.0000]. The layer has stopped being a blend and become an argmax — and a saturated softmax hands almost no gradient to the vectors responsible. Dividing by √dk pulls the spread back to roughly 1, keeping the distribution soft and the gradients alive.Vaswani et al., §3.2.1: "We suspect that for large values of dk, the dot products grow large in magnitude, pushing the softmax function into regions where it has extremely small gradients."

Notation, if it helps: softmaxrows means "apply softmax to each row independently" — in PyTorch that is dim=-1. Nothing in this lesson is bigger than a dot product.

5 · Watch it work

Here is a hand-built example — 4 tokens ("the trophy fit it"), query width 2, value width 3. The rows of Q and K were picked by hand so the mechanism is visible; in a trained model those are the learned projections instead. Run your code and the numbers below become yours.

Read the grid this way: the row is the token doing the looking, the column is the token being looked at. Row it leans hardest on trophy — but only to about a third. That softness is not sloppiness; it is why gradients can flow to every position and why the layer can carry several interpretations at once.

6 · The same thing in production

Production code does not write those five lines. It calls the fused kernel, which does the same maths with a better memory layout:

import torch.nn.functional as F

out = F.scaled_dot_product_attention(Q, K, V)   # is_causal=False by default: every token sees every token

"Same maths" is checked, not asserted: in this workspace, on float64 inputs, your five lines and this one call agree to within 2.2 × 10−16. What the kernel adds is memory behaviour and a place to put masks and head axes without allocating (T × T) per head — the two things lessons 02 and 03 are about. The docs list the exact hand-written equivalent: PyTorch — scaled_dot_product_attention.
